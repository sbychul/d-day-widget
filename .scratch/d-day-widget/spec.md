# Spec — Notion D-day 위젯

> 불변 조건은 [AGENTS.md](../../AGENTS.md) 2절에 있다. 이 문서의 **사용자에게 보이는 동작**(문구, 형식, 수치, 레이아웃)도 불변이며, 바꾸려면 사용자 승인이 필요하다. 내부 구현 방식은 자유다.

## 1. 개요

Notion 페이지의 `/embed` 블록에 넣는 웹 위젯이다.

- 사용자는 위젯 맨 아래 입력칸에 `날짜 일정명`을 쓰고 Enter를 누른다.
- 일정은 Notion DB에 저장된다.
- 가장 가까운 일정이 크게 표시되고, 나머지는 날짜순 목록으로 표시된다.

```
┌──────────────────────────────┐
│ 2026.10.07 (수)              │  오늘 날짜
│                              │
│ D-10                         │  메인: 가장 임박한 일정
│ 기말고사                      │
│ ──────────────────────────── │
│ D-15  과제 제출            ×  │  목록 (남은 높이, 내부 스크롤)
│ D-20  동아리 MT               │
│ D-79  크리스마스              │
│ ──────────────────────────── │
│ [ 12/25 크리스마스          ] │  입력칸 (항상 표시)
│ 날짜를 알아볼 수 없어요 …      │  오류/상태 줄
└──────────────────────────────┘
```

## 2. 데이터

### Notion DB

| 속성 이름 | 타입 | 내용 |
|---|---|---|
| `이름` | title | 일정명 |
| `날짜` | date | 시작 날짜만 사용 (`YYYY-MM-DD`, 시간 없음) |

- 정렬과 동점 판정에는 Notion 페이지의 `created_time`을 쓴다.
- 보관은 페이지에 `archived: true`를 설정하는 것이다. Notion 휴지통에서 복구할 수 있다.

### 클라이언트·서버 공통 타입

```ts
type Event = {
  id: string;      // Notion page id
  title: string;
  date: string;    // YYYY-MM-DD
  created: string; // ISO 8601 (Notion created_time)
};
```

## 3. 입력 파서 (`src/parse.ts`)

```ts
parseInput(input: string, today: string /* YYYY-MM-DD */):
  | { ok: true; date: string; title: string }
  | { ok: false; error: string }
```

순수 함수다. `today`는 인자로 받는다(테스트 가능하게).

### 규칙

1. 입력 앞뒤 공백을 제거한다.
2. 입력의 **맨 앞**에서 아래 날짜 토큰 중 하나를 찾는다. 위에서부터 먼저 일치하는 것을 쓴다.

   | 형식 | 예 | 연도 |
   |---|---|---|
   | `YYYY[-/.]M[-/.]D` | `2026-12-25`, `2026.12.25` | 명시 |
   | `YY[-/.]M[-/.]D` | `26-12-25` | 명시 (`20YY`) |
   | `M[-/.]D` | `12/25`, `12-25`, `12.25` | 생략 |
   | `YYMMDD` (숫자 6자리) | `261225` | 명시 (`20YY`) |
   | `MMDD` (숫자 4자리) | `1225` | 생략 |
   | `YYYY년 M월 D일` | `2026년 12월 25일` | 명시 |
   | `M월 D일` | `12월 25일` | 생략 |

   - `M`, `D`는 1–2자리, 한국어 형식의 공백은 0개 이상이다.
   - 날짜 토큰 뒤에는 공백이 1개 이상 있어야 하고, 그 뒤가 일정명이다. 공백 없이 붙어 있으면 날짜를 인식하지 못한 것으로 본다.
3. **연도 생략**: `today`의 연도로 정한다. 그 날짜가 `today`보다 이전이면 다음 해로 정한다. `today`와 같으면 올해다.
4. **유효성**: 월은 1–12, 일은 해당 연·월에 실제로 있는 날이어야 한다(윤년 반영). 연도 생략으로 정해진 해에 없는 날(예: 평년의 2/29)이면 오류다.
5. **연도 명시 + 지난 날짜**: `today`보다 이전이면 오류다.
6. **일정명**: 날짜 토큰 뒤 텍스트의 앞뒤 공백을 제거한 값이다. 비어 있으면 오류다. 최대 200자이며, 넘으면 오류다. 글자 수는 유니코드 코드 포인트 기준으로 센다(`[...title].length`). 서버 검증도 같은 기준을 쓴다.
7. **오류 판정 순서**: 날짜 토큰 없음 → 존재하지 않는 날짜 → 연도 명시 + 지난 날짜 → 일정명 없음 → 일정명 초과. 먼저 걸린 오류 하나만 표시한다.

### 오류 문구

| 상황 | 문구 |
|---|---|
| 날짜 토큰 없음 | `날짜를 알아볼 수 없어요 (예: 12/25 크리스마스)` |
| 존재하지 않는 날짜 | `없는 날짜예요` |
| 연도 명시 + 지난 날짜 | `이미 지난 날짜예요` |
| 일정명 없음 | `일정명을 입력해 주세요` |
| 일정명 200자 초과 | `일정명은 200자까지 쓸 수 있어요` |

### D-day 계산

`ddays(today, date) = (UTC(date) − UTC(today)) / 86400000`. 결과가 0이면 `D-Day`, n>0이면 `D-n`이다. 시간대나 서머타임의 영향이 없도록 연·월·일만으로 계산한다.

## 4. 서버 API (`api/events.ts`)

Vercel 함수 1개다. Web 표준 시그니처를 쓰며, 메서드별로 named export한다(`export async function GET(request: Request): Promise<Response>` 등).

공통 사항:
- 환경변수 `NOTION_TOKEN`, `NOTION_DB_ID`를 쓴다. 없으면 500을 반환한다(`{ error: "server not configured" }`).
- Notion 호출 헤더는 `Authorization: Bearer ${NOTION_TOKEN}`, `Notion-Version: 2022-06-28`, `Content-Type: application/json`이다.
- 응답은 모두 JSON이다. 오류 응답은 `{ error: string }` 형태다.
- Notion이 오류로 응답하면 502를 반환하고, Notion의 `message`를 `error`에 담는다.

### 입력 검증 (신뢰 경계)

| 값 | 규칙 | 위반 시 |
|---|---|---|
| `today`, `date` | `^\d{4}-\d{2}-\d{2}$`이고 실제로 있는 날짜 | 400 |
| `title` | 문자열, 앞뒤 공백 제거 후 1–200자 | 400 |
| `id` | `^[0-9a-f]{32}$` 또는 하이픈이 포함된 UUID 형식 | 400 |
| 본문 | JSON 파싱 실패 | 400 |

### 엔드포인트

| 메서드 | 요청 | 동작 | 응답 |
|---|---|---|---|
| GET | `?today=YYYY-MM-DD` | (1) DB 전체(보관 안 된 것)를 `날짜` 오름차순, `created_time` 오름차순으로 조회한다(페이지네이션 끝까지). (2) `날짜`가 있고 `날짜 < today`인 항목을 **순차적으로** 보관한다(Notion 속도 제한 대응). (3) 나머지를 반환한다. | 200 `Event[]` |
| POST | 본문 `{ title, date }` | 페이지를 만든다. | 201 `Event` |
| PATCH | `?id=` + 본문 `{ title, date }` | `이름`, `날짜`를 갱신한다. | 200 `Event` |
| DELETE | `?id=` | `archived: true`로 보관한다. | 204 |

- `날짜`가 비어 있는 페이지(사용자가 Notion에서 직접 만든 경우)는 GET 결과에서 제외하고 보관하지도 않는다.
- POST/PATCH는 지난 날짜를 서버에서 거부하지 않는다(서버는 `today`를 모른다). 파서가 막는다.

## 5. 클라이언트 (`index.html`, `src/main.ts`, `src/style.css`)

### 상태

- `events: Event[]` — 서버 순서를 유지한다. 낙관적 변경 뒤에는 `date`, `created` 순으로 다시 정렬한다.
- `editingId: string | null`
- `pending: number` — 처리 중인 요청 수.

### 표시

- **오늘 날짜**: `YYYY.MM.DD (요일)`. 예: `2026.10.07 (수)`. 요일은 `일 월 화 수 목 금 토`.
- **메인**: `events[0]`. 큰 `D-n`/`D-Day`와 그 아래 일정명.
- **목록**: `events[1..]`. 각 행은 `D-n  일정명` + `×`. 목록 영역은 남은 높이를 채우고 넘치면 내부 스크롤된다.
- **빈 상태**: 메인 자리에 `일정이 없어요`를 표시하고 목록은 비운다.
- **입력칸** placeholder: `12/25 크리스마스`.
- **상태 줄**(입력칸 아래):
  - 수정 중이면 `수정 중 · Esc로 취소`
  - 오류면 오류 문구 (빨간색)
  - 오류 문구는 입력 내용이 바뀌면 지운다.

### 동작

| 동작 | 처리 |
|---|---|
| 로드 | `GET /api/events?today=<로컬 오늘>`. 실패하면 상태 줄에 `불러오지 못했어요` 표시. |
| 추가 (Enter, 수정 중 아님) | `parseInput`이 실패하면 오류를 표시하고 입력을 유지한다. 성공하면 임시 id로 즉시 추가하고 입력칸을 비운 뒤 POST한다. 성공 시 임시 항목을 응답으로 교체한다. 실패 시 임시 항목을 제거하고, 입력칸이 비어 있으면 원래 입력을 복구하며, `저장하지 못했어요`를 표시한다. |
| 수정 시작 | 메인이나 목록 행(× 제외)을 클릭하면 `editingId`를 설정하고 입력칸에 `YYYY-MM-DD 제목`을 채운 뒤 포커스한다. 해당 항목을 하이라이트한다. |
| 수정 저장 (Enter) | 파싱이 성공하면 즉시 반영하고 PATCH한다. 실패하면 이전 값으로 되돌리고 `저장하지 못했어요`를 표시한다. |
| 수정 취소 (Esc) | `editingId`를 해제하고 입력칸을 비운다. |
| 삭제 | `×`를 처음 클릭하면 버튼 텍스트가 `삭제?`로 바뀌고 3초 타이머가 시작된다. 3초 안에 다시 클릭하면 즉시 제거하고 DELETE한다. 실패하면 복구하고 `삭제하지 못했어요`를 표시한다. 3초가 지나면 `×`로 돌아간다. 수정 중인 항목을 삭제하면 수정 모드를 해제한다. |
| 탭/앱 복귀 | `visibilitychange`로 visible이 되면, `pending === 0`일 때 다시 로드한다. |
| 자정 | 다음 로컬 자정 + 1초에 다시 로드하고, 그다음 자정을 다시 예약한다. 다시 로드하면 서버가 지난 일정을 보관한다. |

- `pending > 0`인 동안에는 다시 로드하지 않는다. 진행 중인 낙관적 항목이 덮어써지는 것을 막기 위해서다.
- 같은 날짜의 일정이 여러 개면 `created`가 빠른 것이 메인이 된다(AGENTS.md #16).

### 스타일 (Figma 승인본 기준: https://www.figma.com/design/QmqZtbIUqhJNng8R6xPUVl, 페이지 `02 화면`)

- 방향: **블록형**. 테두리, 배경 박스, 그림자가 없어서 Notion 본문 블록과 구분되지 않는다.

- 팔레트: Figma 변수 `Theme`과 1:1로 대응한다. CSS 변수 이름도 같게 쓴다.

  | 토큰 | Light | Dark | 용도 |
  |---|---|---|---|
  | `bg` | `#FFFFFF` | `#191919` | 위젯 배경 |
  | `text` | `#2C2C2B` | `#F0EFED` | D 숫자, 일정명, 입력값 |
  | `sub` | `#787774` | `#9B9B9B` | 오늘 날짜, 목록 D 열, `수정 중` 상태 줄 |

  출처: Notion Color Reference(Gray text, Gray block highlight, Blue BG, Red text)와 Notion 렌더링 CSS 변수(`--c-bacPri`, `--c-texPri`, `--c-texTer`, `--c-borPri`, `--c-bacInt`).

- 치수 (px):

  | 요소 | 값 |
  |---|---|
  | 위젯 패딩 | 12 (사방) |
  | 세로 간격 (위젯 자식 사이) | 12 |
  | 오늘 날짜 | 12 / Regular / `sub` |
  | Main 블록 | 높이 고정 84. 숫자는 위, 일정명은 아래 끝(space-between). 빈 상태는 문구만 아래 끝. |
  | 메인 숫자 | 48 / Bold / 자간 -2% / `text` |
  | 메인 일정명, `일정이 없어요` | 18 / Medium / `text` |
  | 구분선 | 높이 1. Main 아래와 입력칸 위에 하나씩. |
  | 목록 행 | 높이 34, 좌우 패딩 8, 모서리 4, 행 간격 2, 요소 간격 12 |
  | 목록 D 열 | 폭 52, 14 / Medium / `sub` |
  | 목록 일정명 | 15 / Regular / `text` |
  | `×` | 18 / `placeholder` |
  | `삭제?` | 13 / Medium / `error` |
  | 입력칸 | 패딩 6·8, 요소 간격 8, `+` 18 `placeholder`, 텍스트 15. 테두리·배경 없음. |
  | 상태 줄 | 12 / `sub` 또는 `error` |

- 다크모드는 `@media (prefers-color-scheme: dark)`로 처리한다.
- `×` 노출은 `@media (hover: hover)`에서는 행 hover 때만, `(hover: none)`에서는 항상이다.
- `html, body`는 `height: 100%`이고, 레이아웃은 세로 flex다. 목록에는 `flex: 1; overflow-y: auto`를 준다.
- 접근성:
  - 입력칸에 `aria-label="일정 추가"`를 단다.
  - `×` 버튼에 `aria-label="<일정명> 삭제"`를 단다.
  - 상태 줄은 `aria-live="polite"`로 둔다.
  - 키보드만으로 모든 조작이 가능해야 한다(행은 Enter로 수정 시작).

## 6. 셋업과 배포 (README에 기록)

1. https://www.notion.so/my-integrations 에서 내부 통합을 만들고 토큰을 복사한다.
2. Notion에 전용 DB를 만들고 속성을 `이름`(제목), `날짜`(날짜)로 둔다.
3. DB 페이지에서 `⋯` → 연결 → 1단계에서 만든 통합을 추가한다.
4. DB의 "데이터베이스 ID"를 복사한다. DB 메뉴의 "데이터베이스 ID 복사"를 쓰거나, DB를 전체 페이지로 열었을 때 URL에서 `?v=` 앞의 32자리를 쓴다(하이픈 유무는 상관없다). 부모 페이지의 ID나 "데이터 소스 ID"가 아니다.
5. GitHub 저장소를 만들고 push한다.
6. Vercel에서 그 저장소를 Import하고, 환경변수 `NOTION_TOKEN`, `NOTION_DB_ID`를 등록한 뒤 Deploy한다.
7. Notion 페이지에서 `/embed`를 입력하고 배포 URL을 붙인 뒤 높이를 조절한다.

## 7. 검증

- `npx vitest run`
  - 파서: 7개 형식 각각, 연도 생략 시 올해/내년 경계(오늘, 어제, 내일), 윤년 2/29, 없는 날짜(2/30, 13/1), 연도 명시 + 지난 날짜, 빈 제목, 200자 초과, 공백 없이 붙은 입력.
  - `ddays`: 0, 1, 연말·연초를 넘는 경우.
- `npx tsc --noEmit` 통과.
- `npx vercel dev` + 실제 Notion DB로 확인한다.
  - 추가, 수정, 삭제(두 번 클릭)가 Notion에 반영되는지
  - 어제 날짜 항목을 Notion에서 직접 만든 뒤 로드했을 때 보관되는지
  - 네트워크를 끊었을 때 롤백과 오류 문구가 나오는지
- Notion 임베드 상태로 데스크톱 앱, 웹, 모바일 앱에서 표시·스크롤·다크모드를 확인한다.
